# Lab Setup – Week 9: SOC Introduction & Setup

## 1. Overview
This folder contains the documentation and supporting files related to the lab environment prepared for the DG Interns Hub Week 9 Cybersecurity Internship Assessment. The lab focuses on understanding Security Operations Center (SOC) fundamentals and preparing a controlled virtual environment for network traffic monitoring using Snort Intrusion Detection System (IDS).

## 2. Virtualization Environment
The lab was configured using Oracle VirtualBox on a Windows 11 host system. Virtual machines were used to create an isolated environment for cybersecurity experimentation, network communication, and intrusion detection testing.

## 3. Virtual Machine Configuration
- **Monitoring Machine:** Kali Linux
- **Target Machine:** Ubuntu Desktop 26.04.1
- **IDS Tool:** Snort++ 3.12.2.0
- **Web Server:** Apache HTTP Server
- **Virtualization Platform:** Oracle VirtualBox

Kali Linux was used to monitor network traffic and generate Snort alerts, while Ubuntu Desktop acted as the target system for connectivity and HTTP traffic testing.

## 4. Network Configuration
A host-only network was configured in VirtualBox to enable controlled communication between the virtual machines.

- **Network Address:** `192.168.56.0/24`
- **Kali Linux IP:** `192.168.56.102`
- **Ubuntu Desktop IP:** `192.168.56.101`
- **Monitoring Interface:** `eth0`

The host-only network provided a dedicated environment for testing ICMP and HTTP traffic between the monitoring and target machines.

## 5. Connectivity Verification
Network connectivity between Kali Linux and Ubuntu Desktop was checked before performing intrusion detection tests. ICMP ping testing confirmed successful communication between the systems, providing a baseline for validating the Snort detection rule.

## 6. Snort IDS Preparation
Snort++ was configured on Kali Linux for network traffic monitoring. Its configuration was validated to ensure that the configuration file could be loaded successfully without warnings. A custom rules file was prepared to test ICMP ping detection and HTTP traffic detection.

## 7. Purpose of the Lab
The primary purpose of this setup was to understand how a basic SOC monitoring environment operates, observe network traffic, test signature-based detection rules, and analyze alerts generated by Snort IDS.

## 8. Scope of Testing
The lab included ICMP connectivity testing, HTTP connectivity verification, Snort alert monitoring, and packet inspection using tcpdump. The ICMP detection alert was observed successfully. HTTP connectivity and packet traffic were also verified; however, the custom HTTP Snort alert was not observed and requires further investigation.

## 9. Learning Outcomes
This lab setup provided practical exposure to virtual machine configuration, host-only networking, IP addressing, IDS configuration validation, custom rule preparation, network traffic monitoring, and basic alert verification.

## 10. Folder Contents
This folder is intended to organize the lab setup documentation, network configuration details, relevant commands, supporting evidence, and other files associated with the Week 9 SOC assessment.

**Note:** The environment used Ubuntu Desktop rather than Ubuntu Server. All documented results reflect the tests performed, and any unresolved detection issues are identified transparently.
